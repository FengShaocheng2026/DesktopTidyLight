# 当前架构

版本：MVP 0.1.2。C# / WinForms / .NET Framework 4.8，Windows x64。

## 图标与桌面

`GroupFrame` 是附着到 Explorer 桌面层的窗口；`IconCanvas` 绘制图标、名称、选中状态和滚动条。透明背景使用单独的背景层，图标保持不透明。分组移动不逐个移动原始图标。

`DesktopShell` 集中读取 Shell 项目、稳定文件身份和坐标。成员原始图标停放到所有显示器范围之外；退出或移回桌面时恢复可见位置。应用不移动、复制或删除用户文件。

`LayoutController` / `UnifiedLayout` 负责成员关系和事务：先保存恢复记录，再修改原始图标位置，随后读回验证并提交。失败时回退；成功回退的暂时定位失败可延后重试。保存失败或回退失败停止自动操作，保留恢复记录。

旧的原生图标排列分支仍服务于历史布局兼容与回归检查，不用于新版分组移动。

## 后台工作与资源

- `DesktopScan` 复用一个 STA 后台线程，约每 3 秒枚举桌面。只传递普通数据，每次读取在同一线程创建和释放 COM 对象；过期快照不提交。
- 图标加载由各画布的有界 STA 队列负责，最多 128 个待处理项目。离开可见区域的排队任务会取消，空闲加载线程退出。
- 单元格位图只缓存可见区域，图标缓存覆盖附近页面；刷新、缩放变化和关闭窗口释放对应资源。
- 透明度滑块合并快速输入，数值不变时不保存，松开鼠标提交最终值。
- 不通过强制垃圾回收或裁剪工作集制造内存下降。

## 显示器与持久化

`DisplayLayout` 保存显示器身份、工作区、缩放和首选位置。临时移除显示器时将分组约束到可见区域，保留原显示器记录。`TidyContext` 同时监听环境变化、检查桌面窗口是否重建并比较屏幕工作区。

配置位于 `%LOCALAPPDATA%\DesktopTidyLight\layout.json`，使用原子替换和内部备份。`last-notice.txt` 仅记录最近一次通知，不持续增长。不提供用户手动备份导入或撤销界面。

## 验证入口

`tests/run-checks.ps1` 构建主程序与测试程序，默认执行不修改真实桌面的回归检查。`MvpChecks.exe --desktop-diagnostics` 只读检查当前原始图标、分组及双屏隐藏位置；输出可能含个人文件名，不应提交。

`--performance` 使用临时文件和屏幕外测试窗口；`--unified-render` 验证透明、窗口层级和四种外观。`--unified-shell` 会创建自己的临时桌面项目，应在受控实机验收时单独使用。空闲资源采样运行 `scripts/Measure-Idle.ps1`，输出位于忽略的 `build/review/`。
