# 技术选型与开发方式

日期：2026-10-11。目标：Windows 11 x64、普通用户权限、本地运行、常驻时尽量少占资源。以下是**起步方案**；桌面集成与资源占用要以原型和实测决定。

## 起步技术栈

- **C# + .NET 10（长期支持版）**：一套语言完成界面、配置、托盘和 Windows 接口调用；[微软支持页](https://learn.microsoft.com/en-us/dotnet/core/releases-and-support)列出 .NET 10 支持到 2028 年 11 月。当前开发机只有 .NET 8 SDK，实际创建项目之前需要安装 .NET 10 SDK。
- **WinForms 做分组框和设置界面**：先使用 Windows 桌面控件与必要的自绘，避免引入网页运行环境。WinForms 提供控件、事件、绘制与设计器，适合快速验证桌面操作；这只是开发效率判断，**不是**“一定比其他框架省内存”的实测结论。[微软概览](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/overview/)。
- **只在必要处调用 Windows 原生接口**：桌面图标、托盘、文件图标与右键菜单若现成 .NET 接口不足，再封装对应 Win32/Shell API。优先使用公开、受支持的接口，不把依赖资源管理器内部窗口结构的技巧当成已可靠的方案。
- **本地 JSON 配置**：保存组名、位置、大小、成员和设置；避免为了少量布局数据增加数据库。写入需采用临时文件加替换，并保留可恢复的上一个版本，防止异常退出破坏布局。
- **自启动**：用户开启时写入当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，关闭或卸载时只删除本软件的值，不使用系统服务或管理员权限。Windows 会在用户登录时执行，且用户可在系统启动应用设置中管理；它不表示“尚未登录时运行”。[微软 Run 键说明](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)、[启动应用说明](https://learn.microsoft.com/en-us/windows/win32/w8cookbook/startup-apps)。

## 为何先不采用其他方案

| 方案 | 当前取舍 |
| --- | --- |
| 纯 C++/Win32 | 有机会把运行时依赖和内存压得更低，但原生界面、系统接口和调试的实现成本更高；先用实测判断是否值得付出这笔成本。 |
| Rust + 原生 Windows API | 同样适合系统工具，但桌面 Shell 交互仍需处理，且本机是否具备完整 Windows 编译工具链尚未确认；此阶段不能保证更快交付。 |
| WPF | 视觉定制较方便；分组框第一版界面简单，暂时没有足够理由引入另一套绘制与布局方式。 |
| WinUI 3 | 现代控件较好，但[微软文档](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/unpackage-winui-app)说明未打包应用需处理 Windows App SDK 运行时，独立部署会增加输出体积；当前功能不需要这些额外条件。 |
| Electron / 网页界面 | 没有网页功能需求；额外运行环境对常驻小工具的收益有限，暂不引入。 |

这些是工程取舍，不是跨框架性能排行榜。发布形态先比较依赖已安装 .NET 桌面运行时与自包含包的体积、启动和内存；不预设“单文件”必然更轻。

## 开发顺序与停靠点

1. **小原型**：在隔离的 Windows 11 测试环境中，只实现一个分组和一个测试图标。验证显示、打开、右键、退出恢复、强制结束、资源管理器重启。不能安全恢复就先调整设计，不继续做完整界面。
2. **最小可用版本**：分组增删改、手动加入/移出项目、本地布局保存、托盘、恢复入口、自启动开关。每完成一条需求，按 `mvp.md` 的验收结果手工验证。
3. **资源测量**：在同一 Windows 11 机器上，记录冷启动时间、空闲内存、空闲 CPU、10/100 个图标时的响应，以及发布包大小；与未启动应用的基线对照。异常占用先定位热点，再决定是否替换技术栈。
4. **发布准备**：确定许可证、发布方式、卸载恢复流程和干净机器验证，再公开可下载版本。

## 开发习惯

- 用 Git 小步提交；自动化检查集中在布局读写、恢复状态和自启动开关等有实际风险的逻辑。桌面交互用隔离环境实测。
- 开发和测试时不触碰日常桌面的真实文件。测试图标放在专门的测试账户或虚拟机。
- 不用固定频率轮询桌面；优先响应 Windows 事件。若必须轮询，测量其空闲 CPU 和异常恢复行为。
- 原型通过前，不增加自动更新、遥测、账号、云服务或插件系统。
