# DesktopTidyLight 第一版产品需求（PRD）

状态：开发基线；日期：2026-10-11。以 [MVP 清单](mvp.md)为范围依据。目标系统是 Windows 11 x64；当前没有可运行版本。

## 要解决的问题

桌面上文件、文件夹和快捷方式越来越多时，用户难以按用途找到它们。第一版让用户在桌面上建立少量可命名分组，把现有图标放进分组，继续像普通桌面图标一样使用。软件退出或出错后，用户仍能看到自己的文件与图标。

## 产品原则

1. **不搬动文件**：加入、移出或删除分组只改变桌面显示与布局，不改变文件的实际路径，不复制或删除文件。
2. **用户主导**：首次启动不自动整理；由用户创建分组并手动指定成员。
3. **容易退出**：托盘里始终能退出并恢复普通桌面；开机自启动默认关闭。
4. **轻量可验证**：本地运行、无需账号和网络。性能目标在同一机器的原型测量后填入，不能先写未经验证的数字。

## 核心使用流程

1. 首次打开：桌面保持原样；在桌面空白处右键，可看到“新建分组”。托盘仍提供“新建分组”“设置”“退出并恢复”。
2. 创建分组：点击桌面右键菜单里的“新建分组”，在鼠标附近出现一个有标题的格子；用户可命名、移动和调整大小。若附近空间不足，格子放到当前屏幕的可见区域。托盘新建作为备用入口。
3. 加入项目：用户把已有桌面文件、文件夹或快捷方式拖进格子，松开后成为该组成员；原位置不再额外显示一份相同图标，真实文件路径不变。格子内图标仍按 Windows 默认方式双击打开并支持系统右键菜单。
4. 调整布局：移动或改变分组框大小，成员跟随并保持可见；可把成员移到别组或移回普通桌面。
5. 退出或删除：删除分组只解除分组并恢复其成员的普通桌面显示；托盘退出恢复全部分组。真实文件保持原位。
6. 下次登录：若用户开启自启动，登录 Windows 后自动恢复上次分组；关闭后不启动，也不留下本软件的启动项。

桌面右键菜单是创建分组的主要入口，拖入格子是管理成员的主要手势。这两项要在隔离环境里验证：拖放不得导致真实文件移动或复制；若无法安全做到，应先调整方案并重新评审交互，不以其他手势悄悄替代。

## 需求与验收

| 编号 | 优先级 | 用户需求 | 验收场景 |
| --- | --- | --- | --- |
| M1 | 必须 | 管理分组 | 桌面空白处右键能选择“新建分组”，新格子出现在鼠标附近且可见；能创建至少两个组，重命名、移动、调整大小和删除；删除一个组后，该组成员不丢失，其他组不受影响。 |
| M2 | 必须 | 手动管理成员 | 能把桌面文件、文件夹和快捷方式拖入格子，再移出或转组；每个成员在桌面只显示一次；操作前后真实文件路径不变。 |
| M3 | 必须 | 继续使用文件 | 双击按系统默认程序打开；右键可使用系统菜单；项目已删除或无法访问时给出明确反馈，不打开错误目标。 |
| M4 | 必须 | 保存布局 | 正常退出、重新启动及重启电脑后恢复组名、大小、位置和成员；显示器或缩放变化后，分组仍可在可见区域找回。 |
| M5 | 必须 | 安全恢复 | 托盘退出后普通桌面图标可见；强制结束或 Explorer 重启后不出现文件丢失；提供独立恢复入口。 |
| M6 | 必须 | 基础运行 | 一个用户会话最多运行一个实例；托盘可打开设置、退出和恢复；普通用户权限可用；无账号、网络或后台服务依赖。 |
| M7 | 必须 | 自启动 | 设置里可开启或关闭“登录 Windows 后启动”，默认关闭；开/关后重启验证生效；卸载时清理本软件的启动项。 |

## 边界与异常

- 第一版不做自动分类、文件搜索、云同步、壁纸、标签页、复杂皮肤或 Windows 10 适配。
- 不修改“未加入分组”的桌面项目；如需调整已有图标位置，应先记录并能恢复。
- 遇到 Windows“自动排列图标”等会阻止手动布局的设置时，说明原因并给用户选择，不悄悄修改系统设置。
- 文件被外部程序重命名、删除或 OneDrive 重定向桌面时，分组不能凭旧路径误操作其他文件；具体匹配和恢复策略需在技术原型中验证。
- 无法安全保存或恢复布局时，停止修改桌面布局，并告知用户可用的恢复步骤。

## 发布前验收

- 在隔离的 Windows 11 环境和至少一台日常使用机器上完成 M1–M7 的手工验收。
- 覆盖普通桌面、OneDrive 桌面、Explorer 重启、程序强制结束、重启登录、显示缩放变化。
- 记录冷启动、空闲内存与 CPU、分组操作响应、发布包大小和测试环境；根据结果决定是否需要优化。

首版视觉规格、性能阈值和安装方式在桌面集成原型通过后补充，不以未验证假设阻塞原型。
