# DesktopTidyLight 第一版（MVP）需求草案

状态：已确认第一版方向；日期：2026-10-11。技术实现与量化性能指标仍需验证。

## 目标和边界

面向桌面图标较多、希望手动按用途分组的 Windows 11 用户。第一版只解决现有桌面文件、文件夹和快捷方式的分组、访问与恢复。首个验证和发布目标为 Windows 11 x64；Windows 10 和其他架构暂不纳入第一版承诺。

这里的“图标分组”指用户在桌面上看到可命名的区域，区域内能看到并打开原有项目。分组只是视图/布局，不应因为加入、移出或删除分组而移动、复制、删除真实文件。用户主动通过系统文件操作修改文件时，遵循 Windows 原有行为。

## 必须有

| 编号 | 需求 | 可验收的结果 |
| --- | --- | --- |
| M1 | 创建、重命名、移动、调整大小和删除分组 | 可手动建立至少两个组并按用途命名；删除组后组内项目回到普通桌面显示，真实文件不变 |
| M2 | 手动将现有桌面图标加入、移出和转移到分组 | 文件、文件夹和快捷方式都能操作；组内与桌面上不出现无意的重复图标；操作不改动真实文件路径 |
| M3 | 保留最常用的 Windows 桌面操作 | 组内双击可按系统默认方式打开；右键能使用对应项目的系统菜单；找不到目标或目标已删除时给出清楚提示，不能打开错误项目 |
| M4 | 保存和恢复布局 | 重启程序/电脑后，组名、位置、大小和成员仍在；屏幕变化导致组跑出可见范围时，能把组恢复到可见区域 |
| M5 | 安全退出和恢复 | 用户从托盘退出后，所有被分组的图标重新在普通桌面可见；若异常中断，下次启动或独立恢复入口可恢复普通桌面；不触碰未分组的图标 |
| M6 | 基础运行方式 | 启动后常驻托盘，可打开设置和退出；不要求登录账号或联网；普通用户权限即可运行 |
| M7 | 可选的开机自启动 | 设置中可开启/关闭“登录 Windows 后自动启动”，默认关闭；开启后重启并登录可恢复分组，关闭后下次登录不启动；同一用户会话不会重复运行多个实例；卸载时清除本软件创建的启动项 |

## 第一版暂不做

自动分类规则、全盘文件搜索、文件夹映射、云同步、AI、壁纸、标签页、复杂皮肤、跨设备布局、Windows 10 和其他平台支持。这些功能不会写进第一版验收范围。

## 技术验证关口

在开始完整界面前，先做一个可丢弃的小原型，在隔离的 Windows 11 测试环境中验证：读取桌面图标、将原生图标排入分组区域、双击/右键操作、退出和异常中断后的恢复。重点检查资源管理器重启、显示缩放、多显示器、OneDrive 桌面重定向。若图标定位、分组框交互或原位置恢复无法可靠实现，应重新评估交互方案，不能用搬动用户文件来冒充同一功能。通过后才在日常使用的桌面试用。

## 验收环境和量化指标（技术验证后填写）

- Windows 具体版本、分辨率、缩放比例和显示器组合。
- 安装包体积、首次启动时间、空闲内存/CPU、拖动响应时间；需在同一机器和同一测量方法下记录。
- 包含普通桌面、OneDrive 桌面、资源管理器重启、程序崩溃、开关机及自启动开关的恢复测试记录。
