# 第一版技术实现与验证计划

状态：图标定位已完成本机初步验证，完整分组交互未通过实机验证；日期：2026-10-11。产品行为见 [PRD](prd.md)，技术栈见 [技术选型](technical-approach.md)。

## 实现路径

第一版主程序采用 C#、WinForms 和 .NET Framework 4.8，通过 Win32/Shell 接口尝试让**Explorer 的原生桌面图标**按组排在桌面上，再画轻量分组框。这样图标的双击、右键与文件操作仍由 Explorer 负责，不需要复制图标或移动真实文件。Windows 公开的 [IFolderView::SelectAndPositionItems](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifolderview-selectandpositionitems)提供图标定位能力；本机仅验证了临时测试图标的移动和立即恢复，其他场景仍须原型验证。

这里的“分组”是本软件保存的成员关系和可见区域，不是把图标装入 Windows 提供的原生分组容器。桌面项目也不限于快捷方式，还包括普通文件、文件夹和虚拟 Shell 项目；不能靠修改 `.lnk` 文件实现通用分组。位置接口只能证明可尝试调整图标坐标，不能证明分组框能与图标正确叠放、接收拖放或在“自动排列”开启时保持布局。不要把“隐藏原图标并自己画一份”当作已经确定的实现。

若分组框无法稳定放在图标周围、拖动行为会误触文件操作，或 Explorer 重启后布局不可恢复，则暂停此路径。不要用移走真实文件或隐藏所有桌面图标来“完成”需求。当前原型为了让格子位于普通应用之后，**依赖 Explorer 的 `Progman` / `SHELLDLL_DefView` 窗口层级**；这不是稳定的公开桌面窗口扩展契约，必须通过 Windows 更新和 Explorer 重启验收，不能把本机一次层级检查当作兼容性保证。

Windows 11 主右键菜单的接入也单独验证。微软的[菜单扩展文档](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)使用 `IExplorerCommand` 和应用包身份；未打包程序可采用 sparse package。先验证命令能否只在桌面空白处出现、能否把点击位置交给主程序，以及安装和卸载是否可靠。旧式注册可能落在“显示更多选项”，不能未经验证就把它当作 PRD 所需的桌面右键入口。

## 原型先验证的六件事

1. 通过公开 Shell 接口读取测试桌面项目的身份、位置与显示信息。
2. 在更改位置**之前**保存一份原位置记录；只对专门的测试图标调用定位接口。
3. 用不遮挡原生图标输入的分组框围住它，验证双击、右键、拖入格子、移出格子、选中及桌面空白处操作；拖放不能移动或复制真实文件。再验证多选三个混合类型图标后一次拖动，失败时整批保持原布局。
4. 退出和删除组后将测试图标恢复原位；如果原位已被其他图标占用，不覆盖其他项目，给出可见且可恢复的结果。
5. 强制结束进程、重启 Explorer、修改缩放后检查图标仍可见；重新启动或独立恢复命令能读取记录并恢复。
6. 检查 Windows 自动排列、桌面图标隐藏、OneDrive 桌面重定向对上述流程的影响；按 Win+D、Alt+Tab、打开和最小化普通窗口时，格子必须表现为桌面的一部分。

目前的自动化测试只移动明确创建的临时测试图标，不自动移动用户已有图标。用户已允许在本机测试，前提是不丢失原图标、不抢占电脑。完整界面已有原型代码，但上面的交互验收仍是发布关口。

## 组件边界

| 部分 | 职责 | 关键约束 |
| --- | --- | --- |
| 桌面 Shell 适配 | 枚举原生图标，读取和设置位置，识别文件、文件夹与快捷方式 | Shell/COM 调用集中在一处；不把窗口句柄当作持久身份。 |
| 分组模型 | 组名、矩形、成员和拖动布局计算 | 不直接执行文件移动或删除；便于独立测试。 |
| 分组框 | WinForms 自绘背景、标题和边界；处理移动与调整大小 | 图标所在区域不能拦截原生双击、右键或拖放；按事件重绘。 |
| 配置与恢复 | 保存布局、项目身份、原位置与进行中的调整 | 更改图标位置前先持久化恢复记录；写入使用临时文件和可恢复副本。 |
| 桌面右键入口 | 在桌面空白处提供“新建分组”，把点击位置传给主程序 | 验证 Windows 11 菜单可见性、注册与卸载；菜单扩展不得拖慢 Explorer。 |
| 托盘与设置 | 备用新建组、退出恢复、独立恢复入口和自启动开关 | 一个用户会话只运行一个实例；自启动默认关闭且只改本软件的 Run 值。 |

配置默认放在当前用户的本地应用数据目录，采用带版本号的 JSON。原型验证项目身份的持久化形式：优先使用 Shell 可解析身份，并处理路径变化；不能凭文件名猜测要恢复的目标。恢复失败时保留记录，不静默丢弃。

## 恢复策略

本方案的原生图标始终留在桌面上，程序崩溃也不应使文件或图标消失；恢复主要是撤销本程序造成的位置变化和分组框。首次改变位置前写入恢复记录，完成布局保存后标记当前状态。下次启动若发现未完成记录，先提供恢复普通桌面的入口，不继续自动整理。Explorer 重启后重新取得 Shell 接口和图标身份，不能复用旧句柄。

托盘退出时恢复程序接管的图标位置并关闭分组框。用户后来主动移动过的图标不应被盲目覆盖；冲突处理规则需在原型中验证。卸载前应调用同一恢复流程，之后清理本软件的自启动值。

## 界面与资源

第一版只有一套基础风格。绘制层独立于分组数据，未来可以改颜色、字体、圆角和透明度，但不建皮肤插件系统。先用 WinForms 自绘；确需复杂图形时再评估其他系统绘制接口。只在内容或窗口变化时重绘，图标信息按需读取并限制缓存。

资源测量统一在同一台 Windows 11 机器完成，记录冷启动时间、空闲私有内存、工作集、CPU、10/100 个图标响应和构建输出体积。任何“轻量”结论都注明机器、系统版本、显示器与测量方法。

## P0 当前记录（2026-10-11）

此前用 C++ 临时探测程序在本机 Windows 11 x64 读取过 42 个桌面项目，位置读取错误 0；未输出项目名称，也未修改桌面。该工具现已按要求从仓库删除。当前 C# 主程序的只读诊断读取到 41 个项目，自动排列开启。读取成功不代表完整分组交互通过。

补充验证：探测工具新增只读的 `--selected` 模式，本机在未选中图标时返回 0；这只验证了空选择的处理，尚未验证多选拖放。当前机器是 Windows 11 家庭中文版，没有 Windows Sandbox 可执行入口；[微软说明](https://learn.microsoft.com/en-us/windows/security/threat-protection/windows-sandbox/windows-sandbox-overview)家庭版不支持 Windows Sandbox。随后用户授权在本机用临时测试图标做不抢焦点的定位实验。

## P1 本机初步记录（2026-10-11）

用户已允许在本机桌面测试图标位置，能接受布局被打乱，但要求不丢失原图标、测试时不占用电脑。使用只创建临时文本文件的后台命令行探测：自动排列开启时，`SelectAndPositionItems` 返回成功，但图标位置没有变化。临时关闭自动排列和对齐到网格后，同一测试图标从 `(4256,861)` 移到 `(4280,885)`，随后回到原坐标；两项设置均恢复为开启。测试文件已删除，桌面项目数量回到 41，位置读取错误 0。桌面视图的 `IFolderViewOptions::SetFolderViewOptions` 返回 `E_NOTIMPL`，但 `IFolderView2::SetCurrentFolderFlags` 在本机可切换自动排列状态。

这只验证图标定位和立即恢复，没有验证原生拖放、多选、Win+D、Explorer 重启或程序崩溃。产品不能把定位接口返回成功等同于图标真的移动；必须回读位置。首版也不能在用户不知情时永久改变“自动排列”设置。

## C# 原型实测与剩余验收（2026-10-11）

- 旧 C++ 工具已删除。C# 调用 Shell 接口读到 41 个桌面项目；用专用临时文件在关闭自动排列的短时间内移动 24 像素并恢复原坐标，随后自动排列恢复开启，临时文件数量为 0。
- 顶层格子在测试中遮住 Chrome，因此改挂到 Explorer 桌面视图。后台短暂检查表明格子是桌面视图中位于图标列表上方的子窗口，Chrome 仍盖在格子上面，且格子没有获取前台焦点。已验证透明区域在顶层测试时不拦截下层窗口；**尚未在真实桌面手动验证原生图标拖放和点击穿透**。
- 图标坐标使用桌面列表视图坐标。本机列表视图原点为 `(-2194,-2)`，与虚拟屏幕原点相同；原型以虚拟屏幕原点换算格子命中区域。不同屏幕组合和缩放尚未验证。
- 布局 JSON 的保存、读取和备份恢复已后台验证。分组前保存桌面项目位置快照，异常中断后保留原位置记录；但强制结束、Explorer 重启和位置冲突的完整流程尚未验收。
- 无分组托盘状态一次测得私有内存 24.1 MiB、工作集 52.8 MiB，后续 5 秒 CPU 时间增加 0.016 秒。本机两块显示屏，仅供基线比较，不能代表有分组后的资源占用。
- 当前桌面右键通过当前用户的旧式 `DesktopBackground\\Shell` 注册，Windows 11 主菜单可见性未验证；按[微软文档](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)，主菜单接入需要原生 `IExplorerCommand` 和应用包身份。
- 原生 `IExplorerCommand` DLL 与稀疏包清单现已能离线构建，尚未签名、注册或在 Explorer 中验收。具体限制见[菜单接入记录](menu-integration.md)。M1–M7 **均未宣告通过完整验收**。
